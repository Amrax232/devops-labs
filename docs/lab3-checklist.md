## Порядок проведения изменения (пункт 15)

```bash
git switch main && git pull
git switch -c feature/10-write-offs        # задача #10 «Списание материалов»

# коммиты по шагам, каждый — законченная мысль:
#   refactor: правила предметной области вынесены в app/domain.py
#   feat: телефон поставщика, место хранения и списание материалов (миграции 0002–0004)
#   test: тесты по уровням — API с граничными случаями и интеграционные на PostgreSQL
#   chore: проверочный контур make verify — SAST, покрытие, мутации, политика качества
#   feat: резервное копирование с проверкой архива, демонстрации восстановления и миграций
#   docs: стратегия тестирования, матрица ТЗ, политика качества, миграции, резервные копии

make verify                                 # все 7 шагов зелёные
git push -u origin feature/10-write-offs   # merge request: вывод make verify — в описание
```

В описание merge request прикладывается итог `make verify` и ссылки на отчёты
покрытия и мутаций; критические файлы (`Makefile`, `pyproject.toml`,
`migrations/**`, `scripts/check_policy.py`) отмечаются отдельно.

## Сценарии защиты

### 1. Преподаватель меняет условие в основной логике — тесты должны это поймать

Любое условие в `app/domain.py`, например в `apply_write_off`:

```python
if requested > current:        # заменить на  >=
```

```bash
make test-unit
# FAILED tests/unit/test_domain.py::test_write_off_of_whole_stock_is_allowed
```

Другие примеры: `<` → `<=` в `is_below_min` (падает граница «остаток = минимуму»),
`< 1` → `< 2` в `ensure_can_post` (падает «документ с одной строкой проводится»),
удаление `ensure_draft(...)` (падает «проведённый документ провести повторно
нельзя»). Именно такие изменения перебирает `make mutation` — 35 мутантов,
все убиты.

### 2. Миграции на чистой и на заполненной базе

```bash
make up
make migrations-demo        # во временной базе, рабочая не трогается
make test-integration       # то же автоматически + лестница и сверка моделей
```

### 3. Резервная копия, повреждение, восстановление

```bash
make seed
make restore-demo
```

или вручную по шагам из [`backup.md`](backup.md).

### 4. Назначение каждой команды в `make verify`

| Шаг | Отвечает на вопрос |
|---|---|
| `policy` | не ослабил ли кто-то тесты и анализаторы? |
| `secrets` | не утекли ли пароли, ключи и данные в репозиторий? |
| `lint` | соответствует ли код единому стилю и нет ли явных ошибок? |
| `sast` | нет ли в коде известных шаблонов уязвимостей? |
| `test-db` | готова ли изолированная тестовая база? |
| `coverage` | работает ли всё, что описано в ТЗ, на SQLite и PostgreSQL, и достаточно ли кода проверено? |
| `mutation` | действительно ли тесты ловят ошибки в правилах, а не просто выполняют строки? |
