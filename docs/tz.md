# Техническое задание

**Проект:** складской учёт (вариант №1)
**Курс:** «Методология и практики DevOps»
**Версия:** 0.1.0 (лабораторная работа №1)

## 1. Назначение системы

Система предназначена для учёта товарно-материальных ценностей на складе
предприятия: ведения справочников материалов, единиц измерения и поставщиков,
регистрации документов поступления и получения актуальных сведений об остатках.

Система заменяет ручной учёт в таблицах и решает три задачи:

1. хранить единый непротиворечивый справочник номенклатуры;
2. фиксировать поступления материалов документами, а не правкой остатков вручную;
3. давать отчёт об остатках и о поступлениях за период.

## 2. Категории пользователей

| Пользователь | Задачи |
|---|---|
| Кладовщик | оформляет и проводит документы поступления, смотрит остатки |
| Снабженец | ведёт справочники поставщиков и материалов, следит за позициями ниже минимума |
| Руководитель склада | смотрит отчёты по остаткам и по поступлениям в разрезе поставщиков |

Разграничение прав в версии 0.1.0 не реализуется (задача последующих работ).

## 3. Основные сценарии использования

1. **Наполнение справочников.** Снабженец заводит единицы измерения, поставщиков
   и материалы. Для материала указывается минимальный остаток.
2. **Регистрация поступления.** Кладовщик создаёт документ поступления
   (номер, поставщик, дата), добавляет строки «материал — количество — цена».
   Документ находится в статусе «черновик» и может редактироваться.
3. **Проведение поступления.** Кладовщик проводит документ: остатки материалов
   увеличиваются, документ становится неизменяемым.
4. **Контроль остатков.** Руководитель запрашивает отчёт по остаткам, при
   необходимости — только позиции ниже минимального запаса.
5. **Отчёт по поставщикам.** Руководитель запрашивает сводку проведённых
   поступлений за период в разрезе поставщиков.

## 4. Функции системы

| № | Функция | Реализация |
|---|---|---|
| Ф1 | Ведение единиц измерения | `GET/POST/DELETE /api/v1/units` |
| Ф2 | Ведение поставщиков | `GET/POST/PATCH/DELETE /api/v1/suppliers` |
| Ф3 | Ведение материалов | `GET/POST/PATCH/DELETE /api/v1/materials` |
| Ф4 | Поиск материалов по названию и артикулу | `GET /api/v1/materials?q=` |
| Ф5 | Регистрация документа поступления | `POST /api/v1/receipts` |
| Ф6 | Редактирование строк черновика | `POST/DELETE /api/v1/receipts/{id}/items` |
| Ф7 | Проведение поступления с изменением остатков | `POST /api/v1/receipts/{id}/post` |
| Ф8 | Отчёт по остаткам | `GET /api/v1/reports/stock` |
| Ф9 | Отчёт по поступлениям за период | `GET /api/v1/reports/receipts` |
| Ф10 | Проверка работоспособности сервиса | `GET /healthz`, `GET /readyz` |

## 5. Сущности

| Сущность | Таблица | Описание | Ключевые атрибуты |
|---|---|---|---|
| Единица измерения | `units` | как измеряется материал | `code` (уникален), `name` |
| Поставщик | `suppliers` | контрагент, поставляющий материалы | `name`, `inn` (уникален), `email`, `is_active` |
| Материал | `materials` | номенклатурная позиция с текущим остатком | `sku` (уникален), `name`, `unit_id`, `quantity`, `min_stock` |
| Поступление | `receipts` | документ прихода на склад | `number` (уникален), `supplier_id`, `received_at`, `status`, `posted_at` |
| Строка поступления | `receipt_items` | материал, количество и цена в документе | `receipt_id`, `material_id`, `quantity`, `price` |

## 6. Связи между сущностями

- `units` 1 — N `materials`: у материала ровно одна единица измерения.
- `suppliers` 1 — N `receipts`: документ оформляется на одного поставщика.
- `receipts` 1 — N `receipt_items`: документ состоит из строк (удаление
  документа каскадно удаляет строки).
- `materials` 1 — N `receipt_items`: материал встречается в разных документах,
  но в одном документе — не более одного раза.

Схема с ER-диаграммой: [`db-schema.md`](db-schema.md).

## 7. Ограничения и правила

| № | Правило | Уровень контроля |
|---|---|---|
| П1 | Количество в строке документа строго больше нуля | схема запроса + `CHECK` в БД |
| П2 | Цена не может быть отрицательной | схема запроса + `CHECK` в БД |
| П3 | Остаток материала не может стать отрицательным | `CHECK` в БД |
| П4 | Один материал — не более одной строки в документе | `UNIQUE(receipt_id, material_id)` + проверка в коде |
| П5 | Проведение увеличивает остатки; повторное проведение запрещено | правило предметной области |
| П6 | Проведённый документ не редактируется и не удаляется | правило предметной области |
| П7 | Документ без строк провести нельзя | правило предметной области |
| П8 | Нельзя оформить поступление на деактивированного поставщика | правило предметной области |
| П9 | Справочный объект со ссылками не удаляется | проверка в коде + внешние ключи |
| П10 | ИНН поставщика — 10 или 12 цифр, уникален | схема запроса + `UNIQUE` |
| П11 | Уникальны: код единицы, артикул материала, номер документа | `UNIQUE` в БД + проверка в коде |

## 8. Типичные ошибки и их обработка

Все ошибки возвращаются в едином формате:

```json
{"error": {"code": "<код>", "message": "<пояснение>", "details": {}}}
```

| Ситуация | HTTP | `code` |
|---|---|---|
| Некорректное тело запроса (тип, формат, отрицательное количество) | 422 | `validation_error` |
| Объект не найден | 404 | `not_found` |
| Нарушена уникальность или есть зависимые записи | 409 | `conflict` |
| Нарушено ограничение целостности на уровне БД | 409 | `integrity_error` |
| Запрос корректен, но запрещён правилами предметной области | 422 | `business_rule_violated` |
| Прочие ошибки HTTP (неизвестный маршрут, метод) | 4xx | `http_error` |

## 9. Требования к хранению данных

- СУБД — PostgreSQL 16, доступ через SQLAlchemy 2.0.
- Структура базы создаётся **только миграциями** Alembic (`make migrate`),
  правка схемы вручную запрещена.
- Денежные и количественные величины хранятся в `NUMERIC`: количество —
  `NUMERIC(14,3)`, цена — `NUMERIC(14,2)`.
- Индексы: уникальные по `units.code`, `materials.sku`, `suppliers.inn`,
  `receipts.number`; поисковые по `materials.name`, `suppliers.name`,
  `receipts.received_at`, `receipt_items.material_id`.
- Резервное копирование и восстановление — `make backup` / `make restore`
  (`pg_dump`/`pg_restore`, формат custom).
- Параметры подключения задаются переменной окружения `DATABASE_URL` и в
  репозиторий не попадают.
