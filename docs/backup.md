# Резервное копирование и восстановление

## Команды

```bash
make backup                                     # копия в backups/
make restore FILE=backups/warehouse-<дата>.dump # восстановление
make restore-demo                               # копия → порча → восстановление → сверка
```

## Как устроена копия (`scripts/backup.sh`)

| Шаг | Зачем |
|---|---|
| `pg_dump --format=custom` | сжатый архив, восстанавливается целиком или выборочно |
| запись во временный `*.partial`, переименование после успеха | оборванный дамп никогда не выглядит как готовая копия |
| `pg_restore --list` по готовому архиву | архив читается — копия пригодна для восстановления |
| `*.dump.sha256` рядом с архивом | при восстановлении повреждённый файл будет обнаружен |
| ротация: хранится `BACKUP_KEEP` (10) последних копий | каталог не растёт бесконечно |

Если база запущена в `docker compose`, `pg_dump` выполняется внутри
контейнера — версия клиента всегда совпадает с версией сервера. Иначе
(например, на сервере из ЛР2) используется локальный `pg_dump` и `DATABASE_URL`.

Каталог `backups/` исключён из репозитория: копия содержит все данные.

## Как устроено восстановление (`scripts/restore.sh`)

1. **Проверка контрольной суммы.** Не совпала — восстановление не начинается.
2. **Страховочная копия** текущего состояния с префиксом `pre-restore`: если
   восстановили не тот файл, можно вернуться обратно.
3. **`pg_restore --clean --if-exists --single-transaction`**: объекты
   пересоздаются, а вся операция выполняется одной транзакцией. При ошибке
   база остаётся в исходном состоянии, а не «наполовину восстановленной».

## Демонстрация восстановления после повреждения

`make restore-demo` (нужны запущенная база и данные: `make up && make container-seed`):

1. фиксирует состояние: число материалов, строк поступлений, списаний,
   суммарный остаток и контрольную сумму названий материалов;
2. делает резервную копию;
3. **намеренно портит данные**: удаляет все строки поступлений и списания,
   обнуляет остатки, переименовывает материалы в «ИСПОРЧЕНО»;
4. восстанавливает базу из копии;
5. сравнивает состояние с исходным и завершается ошибкой при расхождении.

Пример вывода:

```
==> 1/5 исходное состояние
    материалов: 6, строк поступлений: 6, списаний: 0, остаток всего: 3325.000, контроль имён: 5f1c…
==> 2/5 резервная копия
    Резервная копия сохранена: backups/warehouse-20261015-121500.dump (12K)
==> 3/5 намеренное повреждение данных
    материалов: 6, строк поступлений: 0, списаний: 0, остаток всего: 0.000, контроль имён: a9e2…
==> 4/5 восстановление из backups/warehouse-20261015-121500.dump
    ...
==> 5/5 сверка
    до:      материалов: 6, строк поступлений: 6, ... контроль имён: 5f1c…
    после:   материалов: 6, строк поступлений: 6, ... контроль имён: 5f1c…
Данные восстановлены полностью.
```

## То же вручную (для защиты)

```bash
make backup
docker compose exec db psql -U warehouse -d warehouse \
    -c "DELETE FROM receipt_items; UPDATE materials SET quantity = 0;"
curl -u admin:warehouse123 localhost:8000/api/v1/reports/stock   # остатки нулевые
make restore FILE=backups/warehouse-<дата>.dump
curl -u admin:warehouse123 localhost:8000/api/v1/reports/stock   # остатки вернулись
```
