# Политика качества

Правила обязательны для всех участников и проверяются автоматически командой
`make policy` (`scripts/check_policy.py`), которая входит в `make verify`.

## Что запрещено

| Запрещено | Почему | Как проверяется |
|---|---|---|
| Пропускать тесты (`skip`, `skipif`, `xfail`, `importorskip`) | пропущенный тест не защищает ни от чего, а выглядит как зелёная проверка | поиск по `tests/` |
| Отключать предупреждения анализаторов (`# noqa`, `# nosec`, `# pragma: no cover`, `# pragma: no mutate`) без обоснования | молчаливое исключение прячет настоящую ошибку | поиск по `app/`, `tests/`, `scripts/`, `migrations/` |
| `# noqa` без кода правила, `# nosec` без кода проверки | такая пометка отключает все правила сразу | то же |
| Снижать порог покрытия ниже 80 % | порог превращается в формальность | `[tool.coverage.report] fail_under` |
| Снижать порог мутационного тестирования ниже 80 % | тесты можно ослабить незаметно | `[tool.warehouse.quality] mutation_min_score` |
| Добавлять глобальные и пофайловые исключения ruff | правило отключается для всего кода | сравнение с разрешённым списком |
| Добавлять пропуски проверок bandit | уязвимость перестаёт искаться везде | `[tool.bandit] skips` должен быть пуст |
| Ослаблять запуск pytest (`--deselect`, `-k`, `--ignore`, `-p no:`) | часть тестов перестаёт запускаться | `[tool.pytest.ini_options] addopts` |
| Убирать шаги из `make verify` | проверочный контур становится неполным | разбор цели `verify` в `Makefile` |
| Удалять тесты | проверка формально проходит, но защищает меньше | число тестовых функций не ниже `min_test_functions` в `pyproject.toml` и `TESTS_FLOOR` |
| Убирать этапы или make-цели из CI, `continue-on-error`, `\|\| true`, публикация без всех проверок | сервер перестаёт быть барьером | разбор `.github/workflows/ci.yml` |
| Критический файл без владельца, заглушки в CODEOWNERS | изменение пройдёт без обязательного одобрения | `.github/CODEOWNERS` |
| Принимать уязвимость без обоснования и срока пересмотра | «временное» исключение становится вечным | `security/vulnerability-exceptions.toml` |
| Убирать из шаблона merge request пункты `make verify` и `make container-check` | изменение контейнерной среды попадёт в `main` без проверки | разбор `.github/pull_request_template.md` |
| Образы `latest`, запуск от root, секреты в образе, отключённый healthcheck, лишние порты | см. [`containers.md`](containers.md), раздел 7 | `make container-lint` (`scripts/check_containers.py`) |

## Как оформить обоснованное исключение

Исключение допускается, только если без него нельзя, и оформляется в той же
строке после « - » или « — » (не короче 10 символов):

```python
from app import models  # noqa: F401 - импорт регистрирует модели в Base.metadata

@pytest.mark.skip(reason="...")  # policy - внешний сервис недоступен, задача #42
```

Кроме комментария в коде, исключение обязательно упоминается в описании merge
request и проверяется ревьюером. «Тест мешает» и «линтер ругается» —
не обоснование.

## Пороги

| Метрика | Порог | Где задан | Нижняя граница |
|---|---|---|---|
| Покрытие кода `app` (строки и ветвления) | 80 % | `pyproject.toml` | `COVERAGE_FLOOR` в `scripts/check_policy.py` |
| Мутационное тестирование `app/domain.py` | 80 % | `pyproject.toml` | `MUTATION_FLOOR` в `scripts/check_policy.py` |
| Число тестовых функций | 106 | `min_test_functions` в `pyproject.toml` | `TESTS_FLOOR` в `scripts/check_policy.py` |
| Покрытие требований ТЗ тестами | ≥ 40 % (фактически 100 %) | [`test-matrix.md`](test-matrix.md) | проверяется ревью |

Порог можно **повышать** свободно. Понизить нижнюю границу можно только
изменением `scripts/check_policy.py` — это критический файл: такое изменение
выносится отдельным merge request с обоснованием и одобряется всей командой.

## Состав `make verify`

| Шаг | Команда | Что проверяет | Чем заканчивается при ошибке |
|---|---|---|---|
| 1 | `make policy` | эту политику | список нарушений |
| 2 | `make secrets` | `.env`, ключи, дампы не под контролем версий; в шаблонах нет реальных паролей | список файлов |
| 3 | `make secrets-scan` | секреты во всей истории git (gitleaks) | правило, файл, коммит |
| 4 | `make lint` | формат (`ruff format --check`) и статический анализ (`ruff check`) | список замечаний |
| 5 | `make sast` | уязвимости в коде (`bandit`, средний уровень и выше) | список находок |
| 6 | `make deps-audit` | известные уязвимости зависимостей (pip-audit по `requirements.lock`) | пакет, уязвимость, версия с исправлением |
| 7 | `make container-lint` | запреты для Dockerfile, `.dockerignore` и compose | список нарушений |
| 8 | `make test-db` | PostgreSQL запущен, тестовая база существует | ошибка подключения |
| 9 | `make coverage` | unit, API и интеграционные тесты; порог покрытия; отчёты | упавшие тесты или недобор покрытия |
| 10 | `make mutation` | тесты правил ловят внесённые ошибки | выжившие мутанты |

Те же команды выполняет CI на этапах 1, 2 и 5 ([`ci.md`](ci.md)); весь
pipeline локально — `make ci`.

Шаги идут от быстрых к медленным: если не прошёл формат, тесты не запускаются.
Изменение, для которого `make verify` не проходит, в `main` не принимается.

Изменение контейнерной среды (`Dockerfile`, `.dockerignore`,
`docker-compose*.yml`, `nginx/`) дополнительно требует успешного
`make container-check` — полной проверки с запуском контейнеров
([`containers.md`](containers.md)). Вывод прикладывается к merge request.
