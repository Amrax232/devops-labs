# Правила безопасности развёртывания

Документ фиксирует требования, обязательные для всех сред, где разворачивается
приложение. Нарушение любого из них — основание не принимать развёртывание.

## 1. Учётные записи

| Требование | Как обеспечено |
|---|---|
| Приложение не работает от имени `root` | сервис выполняется от системного пользователя `warehouse` (`User=warehouse` в unit-файле) |
| Под учётной записью приложения нельзя войти в систему | создана с `--system --no-create-home --shell /usr/sbin/nologin`, пароль не задан |
| Администрирование и запуск приложения разделены | администратор — `deployer` (входит в группу `sudo`), приложение — `warehouse` (без sudo) |
| Прямой вход `root` по сети запрещён | `PermitRootLogin no` в `/etc/ssh/sshd_config.d/10-hardening.conf` |

## 2. Аутентификация и доступ

- Вход по SSH только по ключам: `PasswordAuthentication no`, `PubkeyAuthentication yes`.
- Подключаться может только администратор: `AllowUsers deployer`.
- Число попыток и время на вход ограничены: `MaxAuthTries 3`, `LoginGraceTime 30`.
- Доступ к API закрыт логином и паролем (HTTP Basic), значения приходят из
  переменных окружения.

## 3. Сетевые ограничения

| Машина | Разрешено входящее | Всё остальное |
|---|---|---|
| `warehouse-app` (192.168.56.10) | 22/tcp из 192.168.56.0/24, 8000/tcp (API) | запрещено (`default deny incoming`) |
| `warehouse-db` (192.168.56.11) | 22/tcp из 192.168.56.0/24, 5432/tcp **только** с 192.168.56.10 | запрещено |

Дополнительно PostgreSQL слушает только `localhost` и адрес лабораторной сети
(`listen_addresses`), а `pg_hba.conf` разрешает подключение к базе `warehouse`
исключительно с адреса сервера приложения. То есть порт базы закрыт на двух
уровнях: межсетевым экраном и самой СУБД.

## 4. Секреты

- Пароли, строки подключения и учётные данные API **не хранятся в репозитории**.
- В репозитории лежат только шаблоны: `.env.example` и
  `deploy/app/warehouse.env.example` со значениями `CHANGE_ME`.
- Реальные значения находятся в `/etc/warehouse/warehouse.env` на сервере
  приложения: владелец `root`, группа `warehouse`, права `640` — посторонний
  пользователь системы файл не прочитает.
- Пароль пользователя СУБД задаётся переменной окружения при запуске скрипта
  установки и нигде не сохраняется в открытом виде.
- Проверка перед каждым слиянием: `make verify` завершается ошибкой, если файл
  `.env` попал под контроль версий.

## 5. Права на файлы

| Путь | Владелец | Права | Назначение |
|---|---|---|---|
| `/opt/warehouse` | `warehouse:warehouse` | `750` | код и виртуальное окружение |
| `/etc/warehouse` | `root:warehouse` | `750` | каталог конфигурации |
| `/etc/warehouse/warehouse.env` | `root:warehouse` | `640` | секреты: читают только root и сервис |
| `/etc/systemd/system/warehouse.service` | `root:root` | `644` | unit-файл, менять может только администратор |

## 6. Ограничения процесса

В unit-файле включены: `NoNewPrivileges`, `PrivateTmp`, `ProtectSystem=strict`,
`ProtectHome`, `ProtectKernelTunables`, `ProtectControlGroups`,
`RestrictSUIDSGID`, `LockPersonality`. Процесс не может повысить привилегии,
не видит домашние каталоги пользователей и не может писать в системные пути.

## 7. Что проверять при приёмке

```bash
ps -o user,cmd -C uvicorn          # приложение работает НЕ от root
sudo ss -ltnp                      # лишних слушающих портов нет
sudo ufw status verbose            # правила соответствуют таблице выше
sudo sshd -T | grep -E 'permitrootlogin|passwordauthentication'
ls -l /etc/warehouse/warehouse.env # 640 root:warehouse
git ls-files | grep -c '^\.env$'   # 0 — секретов в репозитории нет
```
